## 一、项目定位

企业级**单机版管理中后台底座**（面向中小企业，几百人规模），提供：

- 认证与会话治理（JWT + 会话表混合、单点在线、防爆破、密码有效期）
- 组织与权限（RBAC 双维度：角色管菜单/接口权限，**岗位管审批权限**；部门数据权限自动隔离）
- 审批流引擎（钉钉式：可视化设计、会签/或签/依次、条件分支、驳回至节点、抄送、单据运行时绑定）
- 审计三件套（操作日志 / 登录日志 / 字段级变更日志）
- 消息与实时（站内信 + SignalR 双通道触达、顶栏待办/通知角标）
- 运维内建（定时任务、每日自动备份、迁移版本化、健康探针）
- 业务模块样板（报销单 + 采购申请单，展示"业务接入审批流"的标准模式）

**明确的非目标**：多租户、集群/分布式（Redis/MQ 为可选备用）、多语言、微服务拆分。

## 五、核心机制实现规范

### 5.1 雪花 ID 与序列化
- 主键 long 雪花（Yitter，`Db:SnowflakeWorkerId` 0-63）；插入双通道填充：单条 AOP 自动 + **批量/种子路径显式填充**（种子直连 `Insertable` 必须 `Id = NewId()`，否则多行全为 0 撞主键）
- ⚠️ **红线**：DTO 中雪花 ID 序列化为字符串（`LongToStringConverter`），全局 JSON `NumberHandling.AllowReadingFromString` 读回；前端 id 一律 string
- ⚠️ **红线**：雪花 Id **只在生成器位宽配置一致时**与时间同序——分页默认排序必须用 `CreateTime`，用 Id 会让新数据沉底

### 5.2 泛型仓储与服务
- `IRepository<T>`：CRUD/分页（`Expressionable` 拼条件）/事务/软删除/物理删除/`UpdateWithVersionCheckAsync`/`UpdateWithAuditAsync`
- `BaseService<T>`：`GetRequiredAsync`（不存在抛 NotFound）、`UpdateWithConcurrencyCheckAsync`（**编辑统一入口** = 乐观锁 + 字段审计）
- 分页排序字段反射白名单校验；⚠️ 无效值回退 **CreateTime 而非 Id**（原因见 5.1）

### 5.3 认证与会话治理
- **JWT(2h) + RefreshToken(7天轮换) + sys_user_session 会话表**：每个请求经 `OnTokenValidated` 校验会话存在性 → 登出/踢线/停用即时生效
- 密码 PBKDF2（历史 SHA256 兼容校验）；策略服务端强制；`PwdUpdateTime` + `sys.pwd.expireDays` 超期登录返回 `mustChangePassword` 强制改密
- 防爆破：失败计数（阈值/时长参数化）+ 账号锁定 + 登录/验证码接口限流
- **单点在线**：`sys.login.kickSameUser=1` 时新登录删除旧会话并 SignalR 推送 `force-logout`；被踢端提示后 **2 秒自动回登录页**；401 兜底同样提示+延迟跳转（并发去重）
- **防接管（本次审查修复）**：
  - 重置 admin 账号密码 → 拒绝（本人走改密接口验旧密码）
  - 授予 admin 角色（创建/导入/编辑/分配角色全路径）→ 仅内置管理员本人
  - 修改 admin 账号的角色 → 仅限本人
  - 停用/删除 admin 账号 → 拒绝（原有）

### 5.4 权限（角色管菜单/接口，岗位管审批）
- `[HasPermission("sys:user:add")]` + 动态策略（`perm:` 前缀实时生成）+ 处理器比对用户权限集合（进程缓存，版本号整体失效）
- 菜单树三接口分权：**全量树 `sys:menu:list`**（管理端）、**`tree/my` 登录即可**（管理员全量 / 普通用户角色并集+父级链补全 / 无角色空树）
- 无角色用户：空菜单 → 前端引导 403 友好页（联系管理员分配角色），**不得报错降级**
- 数据权限：实体实现 `IDataScope`（DeptId+OwnerUserId），中间件按角色五档注入全局过滤器，业务零侵入

### 5.5 审计三件套
- 操作日志：全局过滤器记录全部 POST/PUT/DELETE/PATCH（脱敏参数/耗时/IP/成败/错误）
- 登录日志：成功/失败/锁定全记录
- 字段级变更：`UpdateWithAuditAsync` = 乐观锁 + 审计合一（`AuditDiff` 反射 diff → `sys_change_log`；**冲突不落审计、无差异不落审计**；渲染/入库双重 DOMPurify 净化）

### 5.6 乐观锁与跨会话陈旧检测
- `UpdateWithVersionCheckAsync`：**单条 SQL** `SET 业务列+Version+1 WHERE Id=@id AND Version=@旧值`，0 行返回 false
- 服务层 `UpdateWithConcurrencyCheckAsync`：冲突抛 `"数据已被他人修改，请刷新后重试"`
- **完整链路**：返回 DTO 携带 `Version` → 列表回显 → 编辑回显 → 保存回传 → 服务端 `entity.Version = dto.Version ?? entity.Version`（不传跳过，兼容旧客户端）
- ⚠️ **红线**：手工 DTO 映射新增乐观锁字段必须逐一核对（用户模块曾漏 `Version` 导致永远冲突）；**回归测试**：每个乐观锁模块一条"连续编辑两次"用例

### 5.7 审批流引擎（核心）

**DSL（`FlowGraph` JSON，存 `NodeJson`）**：
```json
{ "nodes": [
    {"code":"start","type":"start","next":"c1"},
    {"code":"c1","type":"condition","branches":[
        {"name":"小额","priority":1,"next":"n_low",
         "conditions":[{"variable":"amount","op":"lt","value":10000}]}],
     "defaultNext":"n_high"},
    {"code":"n1","type":"approval","name":"主管审批","mode":"orSign","next":"end",
     "approvers":[{"type":"user","userIds":["..."]},
                  {"type":"role","roleCodes":["..."]},
                  {"type":"position","positionCodes":["..."],"scope":"company|submitterDept"},
                  {"type":"deptLeader","deptId":0},
                  {"type":"submitterChoice"}]},
    {"code":"cc1","type":"cc","next":"end","ccUserIds":[...],"ccRoleCodes":[...]},
    {"code":"end","type":"end"} ],
  "entry":"start" }
```
多规则取并集；条件分支按 Priority 升序求值首个真分支，全不中走 DefaultNext（**解释执行，禁动态编译**）。

**语义清单（实现即验收基准，抄钉钉）**：
- 会签=全员同意才过/任一拒即拒；或签=一人定局其余作废；依次=逐人生成待办（后续 Waiting）
- **自动通过**：审批人=发起人 / 与本实例已审人重复 / 审批人为空——生成 AutoPassed 任务行 + 流转记录
- 拒绝=终态（实例 Rejected、其余任务作废、通知发起人）；重提=新实例从头走
- **驳回至节点**（Return）：作废全部待办 → 目标节点重新生成待办（实例保持 Running）→ 后续节点重新审批；目标=start 时给发起人生成"重新提交"待办，其 approve 后从入口重走
- ⚠️ **退回后必须关闭"重复审批人自动通过"**（查实例 return 记录存在即关闭），否则后续节点被跳过
- 前加签=并入当前节点共同把关；后加签=AppendNodesJson 队列，本节点通过后先进追加节点
- 撤回=仅发起人且无人处理过；转办=原任务 Transferred + 新人生成待办
- 抄送：到达即按人写 `sys_flow_cc`（收件箱数据源）+ 站内信推送
- 通知：任务生成/驳回/抄送/终态均走 `INotifyService`（站内信 + SignalR `notice`/`force-logout` 事件）

**架构约束**：
- 引擎公开方法各自包事务；**内部方法禁止再开事务**（SqlSugar UseTran 不可嵌套）
- 业务回调 `IFlowBusinessHandler` 按 **BusinessTable** 关联（⚠️ 勿按流程编码——编号自增且绑定可换，会失联）：`GetSummaryAsync`（待办标题）+ `OnFinishedAsync`（终态回写，引擎事务内执行）
- FlowCode 系统自增数字串（100 起），多版本同编码唯一启用；`sys_flow_binding` 运行时换绑/停用
- 条件求值 `ConditionEvaluator` 纯函数解释执行；**变量缺失/未知操作符=不命中**（走默认分支）

### 5.8 定时任务（Hangfire 内置作业清单）
| JobId | Cron | 职责 |
|---|---|---|
| sys.log.cleanup | 0 2 * * * | 操作/登录/变更日志 + 过期会话物理删除（保留期参数化） |
| sys.backup.daily | 0 3 * * * | SqlServer 全量备份 + 上传文件增量镜像 + 保留期清理；失败站内信通知管理员 |
| sys.notice.publish | * * * * * | 到期定时公告 Status 2→1 |

- 注册按 `(JobId, Name, Cron, Expression)` 定义数组循环；失败通知管理员 + 上抛自动重试；`[DisableConcurrentExecution]` 防并发

### 5.9 消息与实时
- `INotifyService`（Api 层实现，Service 层只依赖抽象）：落库 sys_message + SignalR 推送双写
- 事件：`notice`（通用通知/待办/抄送/终态）、`force-logout`（互踢/强踢/停用）
- 前端 `useRealtime` 单例连接；**vite 代理 `/hubs` 必须 `ws: true`**

## 七、前端规范

1. 密码 PBKDF2 + 强度策略服务端强制 + 有效期强制改密 + 历史兼容
2. 登录防爆破（失败计数锁定）+ 图形验证码（参数可关）+ 接口限流 + 同账号互踢（参数可关）
3. **防提权四防护**（admin 角色/账号相关操作仅限内置管理员，覆盖建/导/改/分配全路径）
4. 上传：扩展名白名单 + 大小限制 + **magic bytes 内容嗅探**（无签名类型跳过、短内容拒绝）
5. 富文本：渲染与入库双重 **DOMPurify** 白名单净化
6. 敏感数据：日志参数与字段级 diff 词根脱敏（password/secret/token/credential）
7. 操作幂等：`[NoRepeatSubmit]`（用户+路径+参数哈希 2 秒窗口）
8. 会话：JWT 签名密钥生产必须环境变量覆盖；RefreshToken 轮换制

## 九、⚠️ 踩坑红线清单（全部真实发生过，逐条验证过修复）

| # | 红线 | 后果 |
|---|---|---|
| 1 | SqlSugar 查询表达式内**禁止**引用宿主变量的方法调用/三元（`keyword.IsNullOrEmpty() \|\| ...`、`onlyTodo ? ... : ...`） | 生成非法 SQL（"非布尔表达式"）→ 接口 500。条件一律 `Expressionable` 或按分支拆开 |
| 2 | 禁止 `Updateable.WhereColumns(乐观锁列)` 做条件更新 | 以版本列**替换主键条件**，同版本多行被覆盖（数据损坏级） |
| 3 | `UseTran` **不可嵌套**；引擎/服务公开方法各自一个事务，内部方法禁止再开 | 嵌套导致事务行为异常 |
| 4 | `UseTran` 返回 `DbResult` 必须检查 `IsSuccess` 并重抛 `ErrorException` | 异常被吞，业务静默失败 |
| 5 | 雪花 Id 不跨生成器配置比较大小 | 按 Id 排序新数据沉底；分页默认排序用 CreateTime |
| 6 | 手工 DTO 映射新增乐观锁字段（Version）必须逐一核对 | 漏映射=永远发旧版本=编辑永远冲突 |
| 7 | `TryAddScoped` 同接口多实现只收第一个 | `IFlowBusinessHandler` 多实现用 `AddScoped` |
| 8 | 种子/批量 `Insertable` 直连路径不触发雪花 AOP | 多行 Id 全 0 撞主键；显式 `Id = NewId()` |
| 9 | SignalR 开发代理 `/hubs` 必须 `ws: true` | 实时推送全部静默失效，退化为刷新后 401 兜底 |
| 10 | wangEditor 必须在**可见容器**内初始化（弹窗用 v-if 控制创建时机） | 尺寸计算错误/渲染异常 |
| 11 | el-dropdown 命令回调**模板内不做类型运算**（类型断言/注释放 script 函数） | vue-tsc 级联报错满屏 |
| 12 | SFC 具名插槽 `<template #footer>` 必须是组件**直接子级**（不可嵌在 v-if template 内） | vue 编译器崩溃（Cannot read properties of undefined） |
| 13 | el-text 的 type 无 `secondary`；el-tree-select 取值用 `node-key` 不用 props.value | 编译/行为异常 |
| 14 | 菜单种子幂等**哨兵码不得与页面权限码相同** | 查重误判跳过页面创建（待办菜单曾丢失） |
| 15 | `[Phone]`/`[EmailAddress]` 对空字符串也校验 | 选填字段留空必被拦 → 自定义 Optional 特性 |
| 16 | 内置 `[Phone]` 正则宽松（10 位数字也过） | 需严格国内手机号须自定义正则 |
| 17 | CodeFirst 表元数据可能因历史崩溃半残（"')'附近语法错误"） | 逐表初始化定位实体；重建表解决 |
| 18 | 菜单图标：种子清单新增菜单**必须带图标**；全局兜底补默认并告警 | 岗位管理/抄送我的曾漏 |

## 十一、部署

- `docker compose up -d`：**两容器**（panshi-api = .NET+前端静态，8080 对外；panshi-db = SqlServer 2022 带健康检查+数据卷）
- 前端不单独部署（构建产物进 API 容器 wwwroot）；Hangfire 在 API 进程内；Redis/MQ/Nginx 可选
- **必改**：`Jwt__SecretKey`、SA 密码（连接串与 db 服务密码同步）
- **备份卷**：api 与 db 共享挂载备份目录（BACKUP DATABASE 在 db 容器内执行）
- 反向代理时 `/hubs` 需 WebSocket 转发
